## 📋 실행 순서 (Claude Code가 자동 수행)

### 1단계: 컨텍스트 초기화
```
1. KST 기준 현재 날짜·시각 계산
2. 검색 시간 윈도우: 어제 06:30 KST ~ 오늘 06:30 KST (24h)
3. tool_search로 Slack MCP 로드 (slack_send_message) + WebSearch/WebFetch 확보
4. 도구 로드 실패 시 → stderr 기록 후 exit 3
```

### 2단계: 데이터 수집

**(A) AI 뉴스 (web_search ≥5회)**
- 최근 24h(부족 시 48h) · 미국 4~5건 + 한국 1~2건 = 총 5~7건
- 우선: 신규 모델/제품 · 빅테크(OpenAI·Anthropic·Google·Meta·MS·xAI·NVIDIA·Apple) · 사건사고/소송/보안 · 정책규제(백악관·EU AI Act·한국 AI기본법·FTC) · 펀딩/M&A · 한국 빅테크(네·카·삼·LG·KT·SKT)
```
1) "AI news" + 오늘 KST 날짜
2) "OpenAI" OR "Anthropic" OR "Google AI" 최신
3) "AI announcement" OR "AI launch" 24시간
4) "AI regulation" OR "AI lawsuit" 미국
5) "AI 뉴스" OR "인공지능" 한국 최신
```

**(B) 증시 현황 — 지수·급등락은 소스 직접 조회 (web_fetch 필수)**
- **🇰🇷 한국**
  - 지수(코스피·코스닥) 전일대비: `web_fetch` → https://finance.naver.com/sise/
  - 급등 3종목: `web_fetch` → https://finance.naver.com/sise/sise_rise.naver (상승률 상위)
  - 급락 3종목: `web_fetch` → https://finance.naver.com/sise/sise_fall.naver (하락률 상위)
- **🇺🇸 미국**
  - 지수(다우·S&P500·나스닥) 전일대비: `web_fetch` → https://finance.yahoo.com/markets/ (또는 CNBC 마감시황)
  - 급등 3종목: `web_fetch` → https://finance.yahoo.com/markets/stocks/gainers/
  - 급락 3종목: `web_fetch` → https://finance.yahoo.com/markets/stocks/losers/
- **종목별 '이유'**: 종목명으로 web_search 1회씩 보강("<종목명> 상승/하락 이유 오늘"). 확인 안 되면 "이유 확인 중"으로 표기(추측 금지)
- fetch 실패 시: 대체 소스(한국거래소·investing.com·stockanalysis.com/markets/gainers)로 재시도 → 그래도 실패면 해당 항목 "데이터 조회 실패"로 명시

**(C) SNS 4종 (web_search, 플랫폼별 ≥1회)**
```
"Instagram" update OR algorithm OR feature OR issue (24h)
"Threads" (Meta) update OR algorithm OR feature OR news (24h)
"TikTok" update OR algorithm OR ban OR lawsuit OR outage (24h)
"X" OR "Twitter" (Elon Musk) update OR algorithm OR feature OR outage (24h)
```

**(D) 한국 성형·미용 2종 (web_search, 각 ≥1회, 최근 3~7일 허용)**
```
"연예인 성형" OR "성형 의혹" 최신 이슈 (오늘 KST·최근 3~7일)
"성형 부작용" OR "필러 부작용" OR "성형 사고" OR "의료사고" 이슈 (최근 3~7일)
```

**공통 선별 규칙**
- 1차 소스 우선(Reuters·Bloomberg·WSJ·FT·TechCrunch·The Verge·연합·매경·ZDNet Korea·공식 뉴스룸). 재게재·번역·광고성 블로그 제외
- 중복은 가장 권위 있는 1건만. 인용 한 출처당 15단어 미만·1회
- 확인된 1차 소스가 없으면 임의 추정·창작 금지 → "새로운 내용이 없습니다"(또는 "없음")

### 3단계: 슬랙 메시지 작성 — 구성 순서

2. 🌐 글로벌 AI (헤드라인 + 상세요약 + `→ 영향` + 문장 끝 [매체·날짜](url))
3. 🇰🇷 한국
4. 📈 증시 현황 (아래 D 참조)
5. 📱 SNS 업데이트 (아래 E 참조)
6. 💄 성형·미용 (한국)
7. 💡 인사이트 (1줄)
8. 푸터 `_Generated by Claude Code · 다음 브리핑 내일 06:30 KST_`

**레이아웃 원칙**: 구분선(━) 쓰지 않음 · 섹션은 굵은 헤더로 구획 · 출처는 문장 끝 하이라이트 링크로 통합 · 이모지 과다 금지

### 4단계: 슬랙 전송 (분할 발송)

전체가 Slack 1개 메시지 한도(5,000자)를 넘으므로 **2개로 분할**해 같은 채널에 순차 발송:
- **메시지 1/2** — 헤더 + 핵심 3줄 + 🌐 글로벌 AI + 🇰🇷 한국 + 📈 증시 현황
- **메시지 2/2** — 📱 SNS + 💄 성형·미용 + 💡 인사이트 + 푸터

```python
r1 = Slack:slack_send_message(channel_id="C0B5UQZL1NJ", message=<메시지 1/2, 헤더 끝에 (1/2)>)
Slack:slack_send_message(channel_id="C0B5UQZL1NJ", message=<메시지 2/2, 헤더에 (2/2)>)
```
- 각 메시지 5,000자 이내 확인. 여전히 초과 시 3개로 분할
- 사전 승인된 채널 ID 외 발송 금지 · 전송 실패 시 최대 2회 재시도(30초·2분) · 최종 실패 exit 1

### 5단계: 로그 저장 (스레드 댓글)
메시지 1/2의 `message_ts` 스레드에 메타데이터 댓글:
```python

• 쿼리: AI <n> + 증시(web_fetch) 6소스 + SNS 4 + 성형 2
• 채택 뉴스 <n>건 · 증시: KR 지수2+급등3+급락3 / US 지수3+급등3+급락3
• SNS: 인스타/쓰레드/틱톡/X 각 4항목 · 성형: 연예인/부작용
```
